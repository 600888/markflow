# MarkFlow 自定义模板工作台设计方案

## 1. 设计结论

当前 520px 弹窗承载了基础信息、四级标题、正文、代码、页眉和表格等全部配置，且多个折叠区默认展开。主要问题不是字段本身太多，而是任务层级、编辑焦点和结果反馈都挤在同一个滚动容器里。

本方案将自定义模板从“小弹窗”升级为独立工作台，采用：

- 左侧：四步任务导航与完成进度。
- 中间：当前步骤的属性编辑；同类对象使用轻量 Tab。
- 右侧：固定的实时文档预览，不随表单滚动消失。
- 顶部：返回、草稿状态、导出预览、保存并使用。

Pencil 源文件位于 `.pen/markflow.pen`，完整流程包含以下 4 个画板：

1. `01 Custom Template - Basic Info`
2. `02 Custom Template - Typography`
3. `03 Custom Template - Page and Table`
4. `04 Custom Template - Review and Save`

可直接评审的静态预览见 `docs/custom-template-editor-design.svg`。

## 2. 信息架构

### 步骤 1：基本信息

- 模板名称：必填，面向用户显示。
- 模板标识 slug：必填，自动建议，可手动修改；保存后默认不可变。
- 用途描述：选填。
- 输出格式：当前至少包含 DOCX；未来可扩展 PDF。
- 创建方式：从推荐样式开始、复制现有模板、导入 reference.docx（后两项属于增强能力）。

### 步骤 2：排版样式

内部 Tab：

- 标题层级：Heading 1–4。
- 正文与段落：字体、字号、对齐、行距、段前、段后、首行缩进。
- 代码块：字体、字号、文字色、背景色。
- 全局字体：中西文字体回退与统一替换。

每个样式对象默认只显示一行摘要；当前编辑项展开完整字段，从而避免四个标题面板同时展开。

### 步骤 3：页面与表格

内部 Tab：

- 页面：纸张、方向、页边距（需要后端新增支持）。
- 页眉页脚：字体、字号、对齐、内容开关；页码位置（部分需要后端新增支持）。
- 表格：表头、表体、对齐、背景色、题注。

### 步骤 4：检查并保存

- 基础信息完整性检查。
- slug 格式与重复校验。
- 不支持或冲突样式提示。
- 样式变更摘要。
- 导出一份真实 DOCX 预览。
- 保存模板并设为当前模板。

## 3. 自定义模板功能清单

### P0：首版必须具备

| 功能 | 说明 | 当前后端能力 |
|---|---|---|
| 创建模板 | 名称、slug、描述、输出格式 | 已支持 |
| 标题样式 | H1–H4 的字体、字号、粗体、颜色、对齐 | 基本支持 |
| 正文样式 | 字体、字号、行距、首行缩进、段前段后、对齐 | 已支持 |
| 代码样式 | 字体、字号、颜色、背景色 | 数据模型支持，需核对渲染完整性 |
| 页眉样式 | 字体、字号、对齐 | 已支持 |
| 表格样式 | 表头、表体、题注相关样式 | 已支持 |
| 实时预览 | 表单变化后 150–300ms 防抖更新右侧示意预览 | 前端新增 |
| 校验 | 必填、slug 格式、重复、非法颜色与数值 | 部分支持，前端补齐 |
| 保存并使用 | 保存后刷新模板列表并设为当前模板 | 保存已有，自动选中需新增 |
| 删除模板 | 二次确认，并说明不可恢复 | 已支持，交互需加强 |

### P1：强烈建议

| 功能 | 用户价值 |
|---|---|
| 编辑已有模板 | 避免“删掉重建” |
| 复制模板 | 以现有模板快速派生 |
| 自动保存草稿 | 防止误关或切换步骤丢失 |
| 单项重置 / 全部重置 | 快速回到推荐默认值 |
| 真机预览 | 生成临时 DOCX/PDF，验证字体与分页结果 |
| 导入 / 导出模板包 | 方便团队共享与备份 |
| 字体可用性检测 | 提前发现目标机器缺少字体 |

### P2：后续增强

- 页面尺寸、方向、页边距。
- 页码、封面、目录样式。
- 图片题注、引用、脚注与列表样式。
- 品牌色与全局设计令牌。
- 模板版本历史、回滚与团队模板库。

## 4. 关键交互规则

1. 打开工作台时创建本地草稿；字段修改后显示“保存中 / 草稿已保存 / 保存失败”。
2. 左侧步骤可以自由切换，不强制线性完成；有错误的步骤显示红点及错误数量。
3. 中间区域一次只展开一个样式对象，其他对象显示“字体 · 字号 · 粗体 · 对齐”的摘要。
4. 右侧预览始终固定；预览支持缩放、A4 页面和示例内容切换。
5. “保存并使用”触发完整校验。第一个错误出现时，自动切换到对应步骤和字段。
6. slug 从名称自动生成，但用户开始手动编辑后停止自动覆盖。
7. 删除、覆盖和离开未保存草稿必须二次确认。
8. 输入框旁仅显示必要帮助；详细解释使用 tooltip，避免再次造成视觉拥挤。

## 5. 响应式策略

- 宽度 ≥ 1280px：三栏完整显示，预览宽 480–540px。
- 宽度 960–1279px：左侧导航收窄为图标 + 标题；预览可折叠。
- 宽度 < 960px：编辑与预览切换为顶栏 Tab；底部操作条固定。
- 工作台建议最小窗口尺寸为 960×680px。

## 6. 视觉规范

- 页面背景：`#F6F7FB`；卡片：`#FFFFFF`；边框：`#E5E7EB`。
- 主色：`#7C3AED`；浅主色背景：`#F3E8FF`。
- 成功状态：`#22C55E`；危险状态：`#EF4444`。
- 卡片圆角 10px，控件圆角 6–7px，主按钮高度 36–40px。
- 正文 12–13px，分组标题 14px，页面标题 20px。

## 7. 现有实现迁移建议

现有 `TemplateEditor.tsx` 的表单状态和 `StyleFields` 可继续复用，但建议拆分为：

- `TemplateWorkbench`：路由、草稿、保存和总校验。
- `TemplateStepNav`：步骤导航与完成状态。
- `BasicInfoStep`、`TypographyStep`、`PageTableStep`、`ReviewStep`。
- `StyleEditorCard`：摘要态 / 展开态。
- `TemplatePreview`：使用统一示例文档渲染即时效果。

首个开发迭代只需要改变前端组织方式，不必修改现有生成 API；编辑、复制、页面设置和模板包导入导出可作为后续 API 扩展。

## 8. 验收标准

- 首屏不出现纵向滚动即可看到当前配置主题、主要字段和完整预览。
- 用户最多两次点击可到达任意样式类别。
- 任一时刻只有一个复杂样式面板展开。
- 保存失败能定位到具体步骤和字段，而不是只弹全局 toast。
- 关闭后重新进入可恢复未提交草稿。
- 键盘 Tab 顺序与视觉顺序一致，所有图标按钮均有文本标签或 aria-label。
